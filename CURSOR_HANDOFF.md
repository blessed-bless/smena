## Развёртывание

1. Получите параметры VPS и SSH-доступ. Проверьте существующие сервисы, reverse proxy, свободные порты и дисковое место. Размещайте приложение в отдельном каталоге, например `/opt/smena`.
2. Выполните `npm test` на Node.js 24+. Для Docker сначала проверьте Dockerfile и `docker compose config --quiet`: обычный `config` может вывести значения секретов.
3. Создайте приватную `.env` по `.env.example`, с правами 600. В compose HOST, PORT и DATA_DIR заданы для контейнера; данные хранятся в named volume.
4. Подготовьте постоянный HTTPS-поддомен с приложением в корне `/` или постоянный туннель. Подкаталог вроде `/smena` в этой версии не поддерживается. Используйте свободный маршрут существующего reverse proxy. Внешний запрос без авторизации должен получать экран входа; `/api/state` должен возвращать 401.
5. До переключения бота можно запустить HTTP-сервер без PUBLIC_URL: polling и настройка меню не стартуют. Проверьте `/health` и хранение данных.
6. После готовности удалённого сервера остановите старый тестовый экземпляр бота на этом ПК. Одновременно должен работать один процесс getUpdates на этот токен. Локальные процессы описаны в `work\smena-private\processes.json`; Stop-Local.ps1 проверяет принадлежность сервера перед остановкой.
7. Задайте PUBLIC_URL и запустите `docker compose up -d --build` либо отдельный сервис Node. Сервер настроит команды и кнопку «Моя смена» автоматически.
8. Проверьте запуск владельцем в Telegram, закрытый доступ посторонним, создание и перенос тестового визита, сохранение после перезапуска, экспорт/восстановление и уведомление. Удаление/очистку реальных данных не используйте как проверку.
